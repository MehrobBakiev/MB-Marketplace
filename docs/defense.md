# Защита ДЗ №2

## Демонстрация за 20 минут

1. **Запуск, 2 минуты.** `docker compose up --build -d --wait`; показать логи Flyway и API, `curl localhost:8080/health`. Открыть `api/openapi.yaml`, объяснить `make generate`, `.gitignore` и использование сгенерированного интерфейса.
2. **E2E, 6 минут.** `make e2e`: регистрация ролей → создание товара и промокода → создание заказа → SELECT таблиц → проверка snapshot → неудачное обновление и rollback → снятие промокода при уменьшении суммы → переход статуса и отмена → возврат остатков → ротация refresh → мягкое удаление → конкуренция за последний товар. Скрипт не печатает пароли и токены.
3. **Альтернативные данные, 4 минуты.** Пустое имя, price=0, stock=-1, неизвестный enum, 51 позиция, quantity=1000, неверный формат промокода. Показать 400 и details. Чужой заказ — 403; отсутствующий товар — 404; неактивный товар и нехватка остатков — 409; невалидный промокод — 422; повторное создание/обновление — 429.
4. **Код и транзакции, 4 минуты.** Открыть `orders.go`, объяснить порядок user → order → products → promo, rollback, partial unique index и snapshot. `make integration` показывает проверку ответов по OpenAPI и конкурентные сценарии.
5. **Теория, 4 минуты.** Подготовить ответы на вопросы ниже.

## Что проверить вручную

| Сценарий | Ожидаемый результат |
|---|---|
| `DELETE /products/{id}`, затем GET и SELECT | Статус ARCHIVED, строка существует |
| Фильтр category с другим регистром/значением | Только точное совпадение |
| Повторное создание раньше N минут | 429 ORDER_LIMIT_EXCEEDED |
| Создание после интервала при существующем CREATED | 409 ORDER_HAS_ACTIVE |
| Запрос qty > stock | 409 INSUFFICIENT_STOCK с product_id, requested_quantity, available_stock |
| Ошибка на втором товаре/промокоде | Остатки первого товара и все остальные записи не меняются |
| Изменение цены товара после заказа | price_at_order и итог заказа остаются прежними |
| Обновление заказа с той же позицией | Старый резерв учитывается при проверке нового количества |
| Промокод на границе min_order_amount | Скидка применяется |
| Уменьшение суммы ниже min_order_amount | Скидка снята, FK NULL, использование возвращено |
| Повторное обновление с исчерпанным собственным промокодом | Скидка сохраняется, если остальные условия соблюдены |
| Отмена CREATED или PAYMENT_PENDING | Остатки и промокод возвращены ровно один раз |
| Отмена PAID, скачок CREATED → SHIPPED | 409 INVALID_STATE_TRANSITION |
| SELLER меняет чужой товар / USER создаёт товар | 403 ACCESS_DENIED |
| USER читает/меняет/отменяет чужой заказ | 403 ORDER_OWNERSHIP_VIOLATION |
| Access истёк / подпись неверна / refresh вместо access | 401 с соответствующим кодом |
| Повторно использован refresh | 401 REFRESH_TOKEN_INVALID |
| Одновременно два заказа на один остаток | Один 201, другой 409; stock=0 |
| Одновременно два использования промокода max_uses=1 | Один 201, другой 422; current_uses=1 |

## Вопросы для подготовки

- Почему OpenAPI здесь источник контракта? Что генерируется, что остаётся ручным? Чем contract-first отличается от описания API по готовому коду?
- Что делают `required`, `nullable`, enum, `minimum`, `multipleOf`, `format: date-time`? Почему create/update/response — разные схемы?
- Почему деньги нельзя рассчитывать через float64? Как округляется скидка? Зачем сохранять price_at_order?
- Что означают ACID и rollback? Почему недостаточно сначала прочитать stock, затем отдельно сделать UPDATE без блокировки?
- Что гарантирует SELECT FOR UPDATE при READ COMMITTED? Почему нужен общий порядок блокировок? Как partial unique index защищает активные заказы?
- Что делают Flyway и flyway_schema_history? Почему нельзя менять уже применённую V1 вместо добавления V2?
- Чем мягкое удаление отличается от физического? Как архивирование влияет на существующие позиции заказа?
- Чем отличаются аутентификация и авторизация? Почему проверка роли не заменяет проверку владельца?
- Из чего состоит JWT? Проверяются ли algorithm, issuer, audience, exp? Почему refresh нельзя использовать как access?
- Зачем ротация refresh и запись jti в БД? Как не выдать два новых refresh при конкурентном запросе?
- Чем 400/401/403/404/409/422/429 отличаются по смыслу?
- Зачем request_id и JSON-логи? Какие поля маскируются? Как связать ответ клиента с записью журнала?
- Почему ДЗ №2 сделано одним приложением? Что усложнится, если вынести каталог и заказы в разные сервисы с разными БД?
